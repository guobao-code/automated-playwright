# Playwright 录制策略

## 推荐策略：分层录制

### 1. 完整业务流程录制（一次性）
录制一个完整的用户操作流程，覆盖所有主要功能模块：

```
登录 → 组织管理 → 成员管理 → 运动记录 → 数据统计 → 系统设置
```

**优点：**
- 一次录制覆盖所有接口
- 自动捕获接口之间的依赖关系
- 测试真实业务场景

### 2. 模块化录制（分模块录制）

如果系统太大，可以分模块录制：

#### 模块1：认证相关
- 登录
- 登出
- 修改密码
- 忘记密码

#### 模块2：组织管理
- 查看组织列表
- 创建组织
- 编辑组织
- 删除组织
- 导入成员
- 导出成员

#### 模块3：成员管理
- 查看成员列表
- 添加成员
- 编辑成员
- 删除成员
- 人脸采集

#### 模块4：运动记录
- 查看运动记录
- 上传运动数据
- 导出运动数据
- 运动统计

### 3. 关键路径录制

只录制核心业务流程：

```
登录 → 创建组织 → 添加成员 → 记录运动 → 查看统计
```

## 录制技巧

### 技巧1：多标签页录制
```bash
# 同时录制多个页面
npx playwright codegen --target=javascript https://www.aisports.cn
```

### 技巧2：录制后生成多个测试文件
录制完成后，手动拆分成多个测试文件，每个文件一个模块。

### 技巧3：使用 Page Object Model
将页面元素和操作封装成类，方便复用。

## 自动化生成测试用例

录制完成后，使用脚本自动生成 API 测试：

```bash
# 分析抓包数据
node scripts/analyze-api.js

# 自动生成所有接口的测试用例
node scripts/generate-all-tests.js
```

## 不需要录制的情况

### 不需要录制的接口：
- 静态资源（图片、CSS、JS）
- 第三方服务（百度统计、微信等）
- 健康检查接口

### 只需要测试一次的接口：
- 只在特定场景触发的接口
- 管理员专用接口
- 已废弃的接口

## 测试覆盖率优化

### 1. 覆盖所有 HTTP 方法
- GET（查询）
- POST（创建）
- PUT（更新）
- DELETE（删除）

### 2. 覆盖所有参数组合
- 必填参数
- 可选参数
- 参数校验
- 参数边界值

### 3. 覆盖所有状态码
- 200（成功）
- 201（创建成功）
- 400（参数错误）
- 401（未认证）
- 403（无权限）
- 404（不存在）
- 500（服务器错误）

## 最佳实践

1. **优先录制核心流程**：登录、组织管理、成员管理
2. **录制边界场景**：空数据、大量数据、特殊字符
3. **录制异常流程**：登录失败、权限不足、网络错误
4. **定期重新录制**：接口更新后重新录制
5. **使用数据驱动**：用不同的测试数据运行同一测试

## 工具辅助

### 查看已录制接口
```bash
# 查看所有已捕获的接口
node scripts/list-apis.js
```

### 查找未测试接口
```bash
# 对比 API 文档和已录制接口
node scripts/find-missing-apis.js
```

### 生成测试报告
```bash
# 运行所有测试并生成报告
npx playwright test --reporter=html
```

## 总结

**不需要每个地方都点！**

建议：
1. 录制 1-2 个完整的业务流程（覆盖 80% 接口）
2. 针对特殊情况单独录制（覆盖剩余 20%）
3. 使用脚本自动生成测试用例
4. 手动补充边界条件和异常测试

这样可以：
- ✅ 节省 80% 的录制时间
- ✅ 覆盖 95% 的接口
- ✅ 测试真实的业务场景
